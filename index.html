THE OPPONENT-DATA DISTINCTION

Does processing timing change what is permitted?

We especially want guidance on the distinction between:

  1. Recording pixels during gameplay.
  2. Processing those pixels during gameplay.
  3. Processing those same pixels only after the match has ended.

Does the timing of processing change whether opponent-board analysis is permitted?

No live output does not, by itself, establish permission to collect structured opponent state.

03 / PRODUCT COMMITMENTS

What Tactrise will not do

The proposal uses screen capture only: visible pixels, not hidden game state. We will modify the architecture if Riot requires additional restrictions.

  • Read TFT or Riot process / client memory
  • Inspect Riot network traffic or packets
  • Inject into the game client
  • Automate gameplay, click or control the game
  • Provide active-match recommendations
  • Provide active-match scouting recommendations
  • Display hidden information
  • Expose opponent tracking during gameplay
  • Intentionally circumvent Vanguard or Riot protections

CURRENT TECHNICAL PROTOTYPE

Research, with uncertainty preserved

Research includes champion identity candidates, HUD validity checks, temporal state transitions, board / bench position candidates, evidence fusion and limited post-game state / decision reconstruction.

Complete automated reconstruction and commercial recognition / coaching accuracy remain unvalidated. Unknown observations stay unknown.

PLANNED DATA HANDLING

Minimal retention, still to be specified

The player would opt in before recording or importing video. Capture would contain visible screen pixels, including opponent boards the player normally views. Pixels, later structured observations and minimal evidence would be used only for post-game review.

The intended flow uses original video only for analysis, deletes it after analysis, and retains results plus minimal necessary evidence. This is a plan, not implemented deletion or a finalized Privacy Policy. Storage, exact retention periods, consent withdrawal, security and evidence/account deletion still need specification.

05 / REQUEST FOR GUIDANCE

Questions for Riot

Please answer A–E individually with YES / NO / CONDITIONAL and any applicable conditions. We are seeking boundary clarification, not completed-product approval.

  1. Is passive screen recording during an active TFT match permitted if there is no real-time processing or output?
  2. Is extracting and storing structured information from the player's own visible screen during the match permitted if it is only used after the match?
  3. Is automated analysis of previously recorded screen pixels permitted after the match has ended?
  4. May opponent-board pixels captured through normal scouting be analyzed only after the match has ended?
  5. Is recognizing and storing opponent-board state during an active match permitted if that information is never displayed or used until the match is over?
  6. Are there any additional restrictions on screen-capture-based post-game analysis that are not covered by the public TFT policies? In particular, how does the September 29, 2026 API-only data-access announcement apply to passive pixel recording, screen OCR and processing an already-completed recording?
  7. Where Riot provides an equivalent supported API or event source, should Tactrise use that source instead of deriving the same information from screen pixels?
